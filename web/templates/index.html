三人小队

竞赛队长 / Orchestrator

负责阶段状态机、分工、共享黑板、checkpoint、返工上限和最终交付。所有交接都写入项目卡片，避免三条线各做各的。

核心协议 skills/team-collaboration-workflow/SKILL.md

建模手 / Modeling Lead

把题面、数据、假设、变量、目标函数、约束和验证方案变成可执行建模卡。

  • 题目解析 agent
  • 数据理解/数据审计 agent
  • 抽象建模 agent
  • 模型选择 agent
  • 验证方案 agent
输出 problem/data/model/review

编程手 / Coding Lead

实现模型、运行实验、生成图表和结果，同时审核数据泄露、边界条件和复现性。

  • 实现 agent
  • 审核 agent
  • 结果整理 agent
输出 code/result/figure/review

论文手 / Paper Lead

按 LaTeX 主格式生成章节，并反查模型、代码、图表、引用和结果一致性。

  • 摘要/标题
  • 问题重述与分析
  • 模型建立与求解
  • 敏感性分析与评价
  • 终稿检查
输出 paper/review

论文产线

LaTeX-first，PDF 与 Word 同源

先把官方 Word 模板解析成 LaTeX 样式，再拼接正文模板与审核后的章节卡，最后编译 PDF 并从同一份源内容导出 Word。

CLI toolbox/cli/mathmodel-report

1. 模板导入

官方 .docx 放入 `toolbox/report/official-word-templates/`。

2. 转换样式

解析页边距、页眉页脚、标题、字体、摘要、题注和参考文献。

3. 拼接正文

正文骨架来自 `body-templates/`，章节内容来自 `paper_section_card`。

4. 编译导出

输出 `paper.pdf`、`paper.docx` 和 `compile_report.json`。

MCP 工具

mathmodel-report-convert-template mathmodel-report-assemble mathmodel-report-preflight mathmodel-report-compile

Checkpoint

默认关口

题目拆解确认需要 problem/data 卡，用户确认题意和附件理解。
模型路线确认需要 model/review 卡，确认变量、假设、约束和验证方案。
核心结果确认需要 code/result/figure/review 卡，确认复现性与数值合理性。
论文初稿确认需要 paper/review 卡，确认图文、公式、引用和结论一致。
最终导出确认需要 paper/result/review 卡，确认 PDF/Word 和编译报告。

阻断规则

数学错误回到 `model_card`，代码错误回到 `coding_task_card`，论文材料缺口回到 `result_card` / `figure_card`。同一问题最多返工 3 轮，超过后由父 agent 要求用户决策。

检索后处理（去重 / 预算）

检索结果会自动按正文规范化去重（合并仅空白不同的重复片段），无需配置。

0 表示与 Top-K 相同；大于 Top-K 时先多取候选再经去重/截断回到 Top-K（上限 200）。
0 表示不限制；按检索顺序整段保留 chunk，超出则丢弃后续。

索引配置

每个块的最大 token 数（默认 512），长文本会被分割成多个块
